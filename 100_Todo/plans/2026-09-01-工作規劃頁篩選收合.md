# 工作規劃頁：篩選列收合成「更多篩選」

> 建立時間：2026-09-01
> 類型：改善優化
> 狀態：待執行

---

## 你要做的事（一句話版）

工作規劃頁的篩選那一排（客戶、類型、優先級、狀態、日期範圍、重複任務、搜尋框、清除篩選，共 8 個）擠成一團、手機上會換行換得很亂。這次把常用的留在外面，其他四個收進「更多篩選」按鈕，點一下才展開。

## 背景和動機

延續 2026-09-01 今日代辦頁摺疊優化那次的方向（`100_Todo/plans/2026-09-01-工作台今日代辦頁摺疊.md`）。
朱兒指出這次「主要是篩選那一排」比較擠，儀表板（進度長條、卡在哪排行榜）這次不動。

朱兒確認：
- **永遠留在外面**：客戶、狀態、搜尋框、清除篩選（這四個佔空間小、也最常用）
- **收進「更多篩選」**：類型、優先級、日期範圍、重複任務，點「更多篩選」按鈕才展開
- **「更多篩選」裡如果選了東西，按鈕要顯示小數字提醒**（避免收起來之後忘記自己篩過什麼）
- **展開狀態每次重置**：不用像卡片摺疊那樣記住雲端狀態，篩選是臨時用的小工具，每次進來都是收起的預設狀態就好

## 具體步驟

### Step 1：篩選列 HTML 重新分組
- 做什麼：`.filters` 裡的 8 個控制項（`#fClient` `#fType` `#fPrio` `#fStatus` `#fRange` `#fRepeat` `#fSearch` `#fReset`）分成兩組：
  常駐區（客戶、狀態、搜尋框、清除篩選）＋一個新的「更多篩選」收合區（類型、優先級、日期範圍、重複任務），
  在常駐區加一顆「更多篩選 ▾」按鈕（含一個數字提醒用的小徽章，預設隱藏）
- 產出：篩選列外觀變成常駐四個＋一顆展開按鈕，收合區預設是關閉的
- 注意：不要更動任何 `select`／`input` 的 `id`，既有的篩選邏輯（`renderTasks` 之類讀 `#fType.value` 的地方）完全不用改

### Step 2：收合區的展開／收起
- 做什麼：點「更多篩選」按鈕切換收合區的顯示／隱藏，用一個單純的 JS 變數或 CSS class 控制（不寫進 `ui`、不同步雲端）
- 產出：點一下展開四個進階篩選，再點一下收起
- 注意：切換分頁或重新整理網頁後，收合區一律回到「收起」的預設狀態（照她的要求，不用記住上次狀態）

### Step 3：收合區裡有篩選時的數字提醒
- 做什麼：類型、優先級、日期範圍、重複任務這四個，只要有任何一個不是預設值（不是「所有類型／所有優先級／不限日期／全部任務」），「更多篩選」按鈕上就顯示啟用中的篩選數量（例如選了 2 個就顯示「2」）；都是預設值就不顯示徽章
- 產出：就算收合區關著，也能一眼看出「現在有進階篩選在作用」，不會忘記自己選過什麼
- 注意：這個數字要在四個 select 的值改變時即時更新，不用等展開收合區才算

### Step 4：手機與電腦都要測過
- 做什麼：本機開發伺服器測試（`python3 -m http.server`），電腦寬螢幕跟手機寬度各測一次：常駐四個是否維持一行不換亂、展開/收起是否正常、數字提醒是否正確出現與消失、既有的篩選功能（點儀表板排行榜跳轉篩選、清除篩選）是否還正常
- 產出：確認沒有破壞現有的篩選邏輯與儀表板連動篩選功能
- 注意：不用她操作，這步是 AI 自己驗證

### Step 5：push 上線
- 做什麼：確認沒問題後 commit + push 到 GitHub，等 GitHub Pages 自動部署完成
- 產出：她打開工作台網址就能看到新版面
- 注意：不用額外通知，她開網頁就會看到

## 預計成果

做完以後你會得到：
- 工作規劃頁的篩選列從 8 個東西擠一排，變成常駐 4 個＋一顆「更多篩選」按鈕，手機上不會亂換行
- 進階篩選（類型、優先級、日期範圍、重複任務）收在按鈕後面，要用才點開
- 就算收起來，只要有進階篩選在作用，按鈕上會有小數字提醒，不怕忘記

## 不包含在這次的範圍

- 不動儀表板的兩塊卡片（進度長條、排行榜）——她確認這次不擠
- 不改變任何篩選邏輯本身，只調整篩選列的呈現方式
- 不做展開狀態的雲端同步（她明確說每次重置就好，跟今日代辦頁的卡片摺疊不同）

## 可能遇到的風險

- **數字提醒的判斷條件遺漏**：如果之後她自己在設定頁改了篩選選項的預設值寫法，這裡「什麼算有篩選」的判斷可能要跟著調整，屬於低機率的邊角案例
- **收合動畫或版面在極窄螢幕（低於 360px）擠壓**：Step 4 會實際測過手機寬度確認
