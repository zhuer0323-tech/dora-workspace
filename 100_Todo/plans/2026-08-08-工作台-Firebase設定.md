## 第 1 步：開啟 Google 登入

1. 開 <https://console.firebase.google.com/>，選專案 **busan-trip-2026-201f8**
2. 左邊選單 → **Authentication（驗證）** → 如果是第一次進來，按「開始使用」
3. 分頁 **Sign-in method（登入方式）** → 點 **Google** → 右上角開關打開 **啟用**
4. 填「專案的公開名稱」隨便填（例如 `Dora 工作台`），「支援電子郵件」選你的信箱 → **儲存**
5. 分頁 **Settings（設定）** → **Authorized domains（授權網域）**
   確認清單裡有 **`zhuer0323-tech.github.io`**，沒有的話按「新增網域」加進去

> 第 5 步很容易漏。少了它，在 GitHub Pages 上按登入會出現 `auth/unauthorized-domain`。

---

## 第 2 步：貼上資料庫規則

1. 同一個專案 → 左邊選單 **Realtime Database** → 上方分頁 **規則（Rules）**
2. 整段換成下面這份 → 按 **發布（Publish）**

```json
{
  "rules": {
    "busan2026": {
      ".read": true,
      ".write": true
    },
    "meetings": {
      ".read": true,
      ".write": true
    },
    "connieScripts": {
      ".read": true,
      ".write": true
    },
    "ws_k7m2q9xr4t": {
      ".read": "auth != null && auth.token.email === 'zhuer0323@gmail.com'",
      ".write": "auth != null && auth.token.email === 'zhuer0323@gmail.com'"
    }
  }
}
```

3. 回工作台重新整理 → 按「用 Google 登入」→ 右上角應該變成綠點「已同步」

> `busan2026`（釜山旅遊）、`meetings`（會議報告）是原本就有的，不要刪。
> `connieScripts` 是 IG 腳本系統一直沒開的，順手一起開。
> 這三個維持公開讀寫，因為它們本來就是要分享給家人／團隊看的。

## 為什麼工作台要登入，其他工具不用

因為工作台的任務裡會有客戶名稱，其他工具沒有。

網頁版 Firebase 的金鑰**一定得寫在網頁原始碼裡**才能運作，藏不住；
網頁上加通行碼也只擋得住點進網頁的人，擋不住直接連資料庫的人。

唯一真正有效的防線是**資料庫規則綁定登入帳號**——沒有用你的 Google 帳號登入，
連一筆都讀不到，就算拿到金鑰、知道路徑名也一樣。

代價是每台新裝置要按一次「用 Google 登入」，之後那台裝置就會記住。

## 常見狀況

| 畫面上看到 | 意思 | 怎麼處理 |
|:--|:--|:--|
| `auth/operation-not-allowed` | 還沒開 Google 登入 | 回第 1 步 |
| `auth/unauthorized-domain` | 網域沒授權 | 第 1 步的第 5 點 |
| `Permission denied` | 規則還沒貼 | 回第 2 步 |
| 「這個帳號沒有權限」 | 用到別的 Google 帳號 | 換成 zhuer0323@gmail.com |
| 登入視窗被擋 | 瀏覽器擋彈出視窗 | 允許此網站的彈出視窗 |
| 右上角紅點「同步失敗」 | 連線出問題 | 點右上角那顆點可以重新登入 |
