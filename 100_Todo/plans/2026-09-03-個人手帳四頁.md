## 你要做的事（一句話版）

把「個人日常紀錄手帳」剩下的空框架補成能用的頁，**分兩批交**：先做每日復盤＋體重紀錄（順便把六維雷達寫死的「快樂 0%」接活），你用幾天之後再做靈感收件匣＋學習時數。

## 背景和動機

9/2 做完「個人」分頁的前三頁（首頁總覽、今日任務、習慣打卡）與雷達總覽，另外五頁還是 `.pstub` 灰卡。其中兩件事現在是假的：

- `pHappyScore()` 直接 `return 0`，六維雷達有一格永遠是 0%
- 首頁的「本月營收」「最新體重」兩格寫死「還沒有紀錄」

這次要把這些接上真實資料。收支記帳那頁**不實作**——你已經有完整的記帳 App（`money/`，含帳戶、轉帳、圖表、LINE 一句話記帳），在工作台再做一份薄的會變成同一件事兩個地方記、數字永遠對不起來。

## 資料結構

沿用 `index.html` 既有的那一套（`LS` 常數 → 頂層 `let` 讀 localStorage → `onValue` 訂閱 → `saveLocal()` ＋ `push()`）：

```
ws_k7m2q9xr4t/
  pReview/{YYYY-MM-DD} = { mood:1..5, good:'', adjust:'', updatedAt }
  pReviewWk/{該週週一的 YYYY-MM-DD} = { next:'下週想先做好的一件事', updatedAt }
  pWeight/{YYYY-MM-DD} = { kg:52.3, fat:24.1|null, updatedAt }
  pIdeas/{id} = { text, note, tag:'heyen|client|video|other', status:'new|todo|done', createdAt }
  pStudy/{id} = { date:'YYYY-MM-DD', mins:50, topic:'', createdAt }
```

目標體重存在既有的 `ui` 節點（`ui.pWeightGoal`），不另開 key——`ui` 已經有 `onValue` 訂閱與 push 流程，直接沿用。

## 具體步驟

### 第一批（先交這批，你用幾天再做第二批）

#### Step 1：資料層打底
- 做什麼：在 `index.html` 加上四個新節點的 `LS` key、頂層變數、`saveLocal()` 的寫入、`onValue` 訂閱（照 `tasks`／`clients`／`rtpl` 現成的寫法複製），再各寫一組 `savePxxx()` / `delPxxx()`。
- 產出：四個節點都能雙向同步，四頁共用，第二批不用再回頭改資料層。
- 注意：`onValue` 回來要走 `saveLocal(); renderAll();` 的既有節奏，不要另外寫一套重繪。

#### Step 2：每日復盤頁（平日 30 秒版）
- 做什麼：`data-ppage="review"` 那個 `.pstub` 換成表單——日期（預設今天，可往回翻）、心情 5 顆表情（😩🙁😐🙂😄，存 1–5）、「今天最好的事」單行、「明天想調整的」單行、存起來。已填過的日子回到那天要帶出舊值可改。
- 產出：每天 30 秒填完，資料進 `pReview`。
- 注意：填過的日期要有視覺提示（例如日期旁一個小點），不然不知道哪天漏填。

#### Step 3：週復盤 ＋ 接上雷達的快樂維度
- 做什麼：
  1. 復盤頁下半部加「這週回顧」區：心情趨勢折線（週一到週日，缺的日子斷開不要補 0）、「這週最好的事」與「這週想調整的」自動把七天的內容列成清單（不用你重打）、「下週想先做好的一件事」一格自由填（存 `pReviewWk`）。
  2. `pHappyScore()` 改成：取最近 7 天**有填**的心情平均，換算 `(avg-1)/4*100`；完全沒資料回 0。
- 產出：六維雷達不再有假資料；週日打開有一頁完整回顧。
- 注意：折線圖照 `dataviz` skill 的規範（單一組資料不放圖例、標題直接說明它是什麼）。

#### Step 4：體重紀錄頁 ＋ 首頁那格接活
- 做什麼：`data-ppage="weight"` 換成——今天體重輸入（一個數字框，體脂選填）、下面一條折線圖（可切 30 天／90 天／今年）、目標體重在圖上畫一條虛線、最近幾筆的清單可點開改或刪。目標體重的設定入口就放在這頁上方。首頁 `renderPHome()` 的 `#pHomeWeight` 改讀最新一筆（顯示數字＋跟上週比的增減）。
- 產出：一天一個數字，首頁看得到趨勢。
- 注意：體重是有小數的，輸入要允許一位小數；同一天重複填算覆蓋不是新增一筆。

#### Step 5：收支記帳那頁改成入口卡
- 做什麼：`data-ppage="money"` 的 `.pstub` 換成一張卡：「💰 收支記帳 → 開啟記帳 App」，連到 `./money/`，底下一行小字說明「生活開銷記在獨立的記帳 App，這裡不重複記」。
- 產出：不再出現「還在規劃中」。
- 注意：連結用相對路徑 `./money/`，跟寶藏工具那張卡的寫法一致。

**➡️ 第一批到這裡驗收：本機開起來四頁點過一遍 → push main → 等 GitHub Pages 更新 → 你在手機上實際填幾天。**

### 第二批（第一批用過之後再開工）

#### Step 6：靈感選題庫（收件匣）
- 做什麼：`data-ppage="idea"` 換成——最上面一個輸入框（打一行字按 Enter 就進來，不用選任何東西）、下面是卡片清單。每張卡可補一句說明、貼一個標籤（禾言／客戶／影片／其他）、切狀態（新點子／想做／做過了）。可依標籤與狀態篩選。
- 產出：想到就丟得進來，之後自己複製去禾言規劃表。
- 注意：**輸入摩擦要低到只打一行字**，任何必填欄位都會讓你懶得記。

#### Step 7：學習時數記錄
- 做什麼：`data-ppage="study"` 換成——日期（預設今天）＋分鐘數（有 25／50 分快捷鈕）＋學了什麼（單行，選填）→ 加一筆。下面是本週長條圖（週一到週日各一根）與本月累計時數，再下面是最近的紀錄清單可刪。順便把首頁那格寫死的「本月營收」改成「本週學習」，讀這裡的資料。
- 產出：看得到自己每週真的花了多少時間學東西。
- 注意：**不動 `pDomainScore()`**——雷達的「學習」維度維持看任務標籤，不要讓時數也去算一份，兩套算法會打架。

#### Step 8：收尾
- 做什麼：push main；把這四頁的規格與踩到的坑補進 `CLAUDE.md` 的工作台那一段與 memory 的 `project_dora_workspace.md`；當日 daily log 記一筆。
- 產出：下次新對話不會忘記這四頁怎麼設計的。

## 可能遇到的風險

- **`index.html` 已經 4531 行，四頁一起塞會很長** → 所以分兩批；每批 push 之前先在本機開起來把九頁點過一遍，確認舊的四頁沒被弄壞。
- **手機版側欄是抽屜** → 新頁切過去之後抽屜要收起來。`switchPTab()` 已經處理了，新頁沿用同一個函式就好，不要另外寫切頁邏輯。
- **復盤設計得漂亮但你不會填** → 這正是分兩批的理由；第一批交完先用幾天，覺得問題不對就在第二批之前調整。
- **兩張折線圖（心情、體重）的顏色** → 走 `dataviz` skill 的規範，改顏色前跑一次它的 `validate_palette.js`，跟記帳 App 那次一樣。
- **Firebase 規則** → `ws_k7m2q9xr4t` 底下整棵樹已經綁你的 email，新開的 key 自動涵蓋，不用動規則。但如果第一批同步不上，先確認是不是 key 名稱打錯而不是去改規則（那份規則是所有 App 共用的，改壞會一起掛）。
