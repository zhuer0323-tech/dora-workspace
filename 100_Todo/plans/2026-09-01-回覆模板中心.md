# 工作台：回覆模板中心

> 建立時間：2026-09-01
> 類型：新功能
> 狀態：待執行

---

## 你要做的事（一句話版）

工作台主導航新增一個「回覆模板」頁籤，把常用的固定留言、回覆內容整理成一個可以分類查找、
一鍵複製的小工具，內文可以帶像 `[客戶名]` 這種方括號變數，用的時候填一填字就自動組好文字。

## 背景和動機

朱兒手邊有不少重複性高的回覆內容（依用途分類，例如詢價回覆、合作邀約、常見問題、感謝訊息），
現在應該是散落著、要用的時候要自己找、自己改字。這次做成工作台裡的一個專屬頁籤，跟現有的
「今日代辦」「工作規劃」同一層級，一打開就找得到、複製了就能貼上用。

這次先只做網頁本身，不接 LINE 小秘書（她確認先求穩，LINE 整合之後有需要再單獨規劃）。

## 具體步驟

### Step 1：資料結構與雲端存放
- 做什麼：在工作台既有的 Firebase 資料裡（`ws_k7m2q9xr4t` 這個節點，跟任務、客戶用同一棵樹）
  新增兩塊：`rtpl`（每則模板：id、分類、標題、內文、建立/更新時間）跟 `rtplCats`
  （分類清單，跟現有「工作類型」設定頁同一套「可以自己新增/改名/刪除」的做法）
- 產出：資料存在雲端，換裝置、換電腦都看得到同一份
- 注意：沿用現有 `push(path, value)` 的寫入方式，不用新增 Firebase 安全規則
  （這棵樹底下新增子節點不用額外開權限，跟今天新增 `ui.cardCollapsed` 時一樣不用動規則）

### Step 2：主導航新增「回覆模板」頁籤
- 做什麼：跟「今日代辦、工作規劃、寶藏工具、專案客戶、復盤、設定」同一排，加一個新分頁
  （沿用現有分頁可拖曳排序、可雙擊改名的機制，新分頁天生就有這些功能）
- 產出：點一下就能切到這個新頁面，跟其他分頁的操作習慣一致
- 注意：分頁名稱預設「回覆模板」，她之後想改名可以直接雙擊改（既有機制）

### Step 3：模板清單畫面（依分類瀏覽＋搜尋）
- 做什麼：頁面上方是分類清單（可橫向切換或側邊列表，依分類數量決定排版），選一個分類顯示
  底下的模板；上面加一個搜尋框，可以直接打字找標題或內文；每則模板顯示標題、內文預覽、
  一顆「使用」按鈕
- 產出：不用一則一則翻，依分類找、或直接搜尋關鍵字都能找到要用的模板
- 注意：分類沒有模板時顯示空狀態提示（沿用其他分頁「目前沒有資料」的呈現方式）

### Step 4：「使用」按鈕：帶變數就跳表單，沒有就直接複製
- 做什麼：點「使用」時，先掃內文裡有沒有 `[變數名]` 格式的方括號文字：
  - **沒有變數**：直接把內文複製到剪貼簿，跳一個「已複製」的提示（跟現有 `toast()` 提示函式一致）
  - **有變數**：跳出一個小表單（沿用 `.modal`/`.sheet` 元件），列出偵測到的每個變數名稱給她填字，
    填完按「複製」，把方括號換成她填的字，組出最終文字複製到剪貼簿並跳提示
- 產出：不管模板有沒有變數，「使用」都是一步到位複製到剪貼簿，可以直接去貼上
- 注意：同一個變數名稱在內文裡出現多次（例如開頭結尾都有 `[客戶名]`）要一次填、全部一起換掉，
  不用重複填好幾次

### Step 5：新增／編輯／刪除模板
- 做什麼：頁面上加「＋新增模板」按鈕，跳出編輯視窗（標題、分類下拉、內文文字框，
  文字框旁邊提示「可以用 `[變數名]` 這種方括號當可換字的地方」）；每則模板可以點開編輯或刪除
- 產出：她可以自己維護模板內容，不用透過我來加
- 注意：分類下拉跟设定頁的「工作類型」一樣，選單裡可以直接新增一個新分類名稱

### Step 6：分類管理
- 做什麼：在「設定」頁或回覆模板頁本身加一小塊分類管理（新增/改名/刪除分類，改名要同步更新
  已經用到那個分類的模板），沿用現有「工作類型管理」的既有邏輯與畫面模式
- 產出：分類架構她可以自己調整，不用寫死
- 注意：刪除一個還有模板在用的分類時要提醒她，或者把那些模板自動歸到「其他」

### Step 7：手機與電腦都要測過
- 做什麼：本機開發伺服器測試，新增/編輯/刪除模板、依分類瀏覽、搜尋、複製（含帶變數與不帶變數
  兩種情況）都跑過一輪，桌面跟手機寬度各測一次；複製到剪貼簿的功能因為瀏覽器安全限制通常要
  HTTPS 才能用，本機測試用 `navigator.clipboard` API 搭配 localhost 通常可以測、真正驗收
  以 GitHub Pages 正式網址（本來就是 HTTPS）為準
- 產出：確認整套流程沒有壞掉的地方
- 注意：不用她操作，這步是 AI 自己驗證

### Step 8：push 上線
- 做什麼：確認沒問題後 commit + push 到 GitHub，等 GitHub Pages 自動部署完成
- 產出：她打開工作台就能看到新分頁，開始建立自己的模板庫
- 注意：一開始模板庫是空的，需要她自己陸續把常用回覆內容加進去（這次不做資料搬移，
  因為目前沒有既有資料可以搬）

## 預計成果

做完以後你會得到：
- 工作台多一個「回覆模板」分頁，可以依用途分類整理常用回覆內容
- 每則模板可以帶 `[客戶名]` `[金額]` 這種可換字的變數，用的時候填一填就自動組好文字
- 一鍵複製到剪貼簿，複製完直接去貼上，不用自己在文字裡找地方改
- 模板跟分類都可以自己新增、編輯、刪除，架構會隨你用的習慣長出來

## 不包含在這次的範圍

- 不接 LINE 小秘書（不能在 LINE 打字直接取得模板內容，這次先只做網頁）
- 不做「依平台分類」（IG/FB/LINE），這次確定用「依用途分類」
- 不搬既有資料進來（目前沒有現成的模板清單可以搬，她要自己陸續建立）
- 不做進階功能（例如模板使用次數統計、多人協作留言），保持單純的個人查找/複製工具

## 可能遇到的風險

- **變數偵測的方括號跟她原本內文裡真的想打的方括號文字衝突**：如果她內文本來就想打普通的
  方括號符號（不是要當變數），會被誤判成變數欄位。機率低，真的發生的話再調整判斷規則
- **分類刪除時模板歸屬問題**：Step 6 已經標注要處理，刪除分類前提醒或自動歸類到「其他」，
  不會讓模板憑空消失
