# 釜山 Pass 48 小時倒數提醒

> 建立時間：2026-07-03 
> 類型：改善優化（釜山旅遊 App 加新功能）
> 狀態：待執行

---

## 你要做的事（一句話版）

在釜山旅遊 App 的行程頁最上方，加一張「Pass 倒數卡片」：現場按下「啟用」開始 48 小時倒數，全家手機同步看得到，快到期前 3 小時卡片變紅色，並主動推播一則 LINE 訊息提醒你。

## 背景和動機

釜山 Pass 一旦啟用就會開始跑 48 小時，容易忘記還剩多少時間、什麼時候會過期。希望 App 能主動提醒，不用自己心算或猜。

## 具體步驟

### Step 1：行程頁加上「Pass 倒數卡片」
- 做什麼：在 `100_Todo/projects/busan-trip/index.html` 的行程頁最上方（行程表標題之上）新增一張卡片
  - 還沒啟用時：顯示「啟用 Pass」按鈕
  - 按下去後：記錄啟用的那一刻，開始顯示即時倒數（幾小時幾分鐘），每秒更新
  - 倒數進到最後 3 小時：卡片變紅色，文字提醒「即將到期，把握時間使用」
  - 超過 48 小時：顯示「已到期」
- 產出：一張會自動倒數、變色提醒的卡片
- 注意：啟用的時間點要存到 Firebase（跟行程、記帳用同一個同步房間 `busan2026`），這樣不管誰打開手機都看到同一個倒數，不是各自獨立算

### Step 2：背景排程檢查 + LINE 提醒
- 做什麼：仿照現有的「廣告快結束提醒」腳本模式，新增一支背景檢查腳本
  - 定期讀取 Firebase 裡記錄的啟用時間，算出還剩多少時間
  - 剩最後 3 小時、而且還沒發過提醒時，發一則 LINE 訊息通知你
  - 發送後做個記號，避免同一次啟用重複發好幾次提醒
- 產出：`scripts/dora-busanpass-checker.sh` + 對應的排程設定（LaunchAgent），比照現有早報/廣告日報的排程方式
- 注意：這個提醒需要你的電腦在旅遊當下保持開機，排程才會被觸發（跟現有的早報、廣告日報限制一樣）

### Step 3：部署與實測
- 做什麼：
  - 把 App 的修改上傳，讓 GitHub Pages 自動更新成新版本
  - 把背景檢查腳本裝到電腦排程裡並啟用
  - 實際測一次：按下啟用、確認倒數有跑、確認剩最後 3 小時時卡片會變色、確認 LINE 提醒有正常收到
- 產出：一個可以直接在旅遊現場使用的完整功能
- 注意：測試時可以先用「假的、很短的到期時間」測 LINE 提醒有沒有正常發送，測完再確認正式用的是 48 小時

## 預計成果

做完以後你會得到：
- 行程頁最上方有一張 Pass 倒數卡片，全家手機同步看到同一個倒數
- 剩最後 3 小時卡片自動變紅色提醒
- 剩最後 3 小時時，會收到一則 LINE 訊息主動通知你

## 不包含在這次的範圍

- 不做「重新啟用 / 重設倒數」功能，這次先假設 Pass 只會啟用一次
- 不做每個景點使用紀錄或扣抵功能
- 不做手機原生推播通知，提醒只透過 LINE

## 可能遇到的風險

- **電腦沒開機**：LINE 提醒不會發送（但網頁上的倒數本身不受影響，隨時打開都準）。處理方式：旅遊期間盡量讓電腦保持開機，或至少在快到期前開一次機。
- **Firebase 測試規則 7/28 到期**：跟現有的行程、記帳同步是同一個限制，這次旅遊（7/7-7/12）不受影響。
- **時區換算誤差**：用統一的時間戳記方式計算剩餘時間，避免因時區換算出錯導致倒數不準。
