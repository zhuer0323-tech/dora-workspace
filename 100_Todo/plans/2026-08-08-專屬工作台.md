## 背景和動機

你現在的狀況有兩個痛點：

1. **工具散落**：釜山旅遊、IG 腳本、會議報告、數學遊戲、報價單，每個都要記各自的網址，沒有一個入口。
2. **Notion 做不到你想要的**：你看到的參考範例（小紅書「動態時間管理計劃表」）能從一張總表自動生出日／週／月／年看板、甘特圖、自動統計與復盤，Notion 排任務排得出來，但這些自動化的看板做不出來。

所以要自己蓋一個。

## 具體步驟

### Step 1：先把「一筆任務長什麼樣」定下來 ✅ 已完成（2026-08-08）

**任務欄位**

| 欄位 | 選項 / 說明 | 必填 |
|:--|:--|:--:|
| 任務名稱 | 自由輸入 | ✓ |
| 大區 | 工作 / 個人 | ✓ |
| 客戶 | 從客戶管理區帶出（工作區才出現） | 工作區必填 |
| 工作類型 | 廣告投放排程、廣告文案、社群文案、素材分析、週報回報、結案報表、操作方向建議、報價單、會議、提案、其他 | ✓ |
| 個人分類 | 家庭、學習、健康、副業、雜事（個人區才出現，取代客戶＋工作類型） | 個人區必填 |
| 優先級 | 🔴 重要且緊急 / 🟠 重要不緊急 / 🟡 緊急不重要 / ⚪ 都不是 | ✓ |
| 狀態 | 🟡 未開始 / 🟣 進行中 / 🟢 已完成 | ✓ |
| 開始日 | 日期 | — |
| 截止日 | 日期（沒填就不進甘特圖、不會超時提醒） | — |
| 預計時段 | 幾點開始 + 做幾分鐘（沒填就只排到「哪一天」，不上時間軸） | — |
| 進度 | 0–100%（狀態設「已完成」自動變 100%） | — |
| 備註 | 自由輸入，可貼連結 | — |

**客戶管理區**（客戶名單不寫死，可自行維護）

| 欄位 | 說明 |
|:--|:--|
| 客戶名稱 | 全名 |
| 顯示簡稱 | 看板上顯示用（例：李享家直播集團 → 李老闆） |
| Google 雲端連結 | 該客戶的雲端資料夾網址，客戶卡上點了在新分頁開 |
| 狀態 | 進行中 / 已結案（已結案移到下拉選單最底下，不影響舊任務統計） |
| 備註 | 自由輸入 |

初始名單：李享家直播集團（李老闆）、漁三、優逸、TOTO、一沐日、沐拾、十八子肉、北元當舖、工研院、內部

**三個設計決定**

1. 「個人分類」與「客戶＋工作類型」互斥，選了個人區就不會被要求填客戶
2. 只有「任務名稱＋大區＋類型＋優先級＋狀態」必填；快速記一筆會自動帶預設值（工作／重要不緊急／未開始）
3. 顏色綁「狀態」（綠紫黃），優先級用左側小圓點表示，不搶顏色

### Step 2：把雲端資料區開好 ⏳ 待朱兒操作（2026-08-08 程式端已完成）

- **做什麼**：在你現有的 Firebase（釜山旅遊那組）開一個新的資料區給工作台用，並綁定成只有你的 Google 帳號讀得到。
- **產出**：手機、電腦、iPad 開同一個網址看到的資料永遠一樣，一邊改另一邊立刻更新。
- **注意**：這一步不會影響釜山旅遊和會議報告的資料，是分開的區域。
- **操作說明**：`100_Todo/plans/2026-08-08-工作台-Firebase設定.md`（要朱兒在 Firebase 主控台按兩個步驟）

**⚠️ 這裡跟原計劃書不一樣，改了做法**

原本寫「加一道通行碼」，實作時發現那擋不住真正的問題：網頁版 Firebase 的金鑰一定得
寫在網頁原始碼裡才能運作，藏不住，所以知道金鑰的人可以繞過通行碼直接讀資料庫。
任務裡有客戶名稱，這個風險不能接受。

改成 **Google 帳號登入 + 資料庫規則綁定 zhuer0323@gmail.com**。沒登入就一筆都讀不到。
代價是每台新裝置要按一次登入（之後那台會記住）。

### Step 3：第一批交付 —— 首頁儀表板 + 任務總表 + 工具捷徑牆 ✅ 已完成（2026-08-08）

實作檔案：`100_Todo/projects/index.html`（單一檔案，含全部四個分頁）
已做的功能超出原本描述的部分：客戶管理區（可自行新增／改名／結案、存 Google 雲端連結）、
勾完成後 4.5 秒內可復原、離線也能用（連上線自動同步）。


- **做什麼**：
  - **首頁儀表板**：大時鐘與問候語、今日聚焦（最多 3 件）、今日進度圓圈（今日完成率、本週完成率、逾期件數）、快速記一筆（一行字直接新增任務）
  - **任務總表**：新增／編輯／刪除／勾完成，可依大區、客戶、類型、優先級、狀態、日期區間篩選，篩完即時顯示統計數字
  - **工具捷徑牆**：釜山旅遊、IG 腳本產出、會議報告閱讀站、數學冒險遊戲、報價單工具，做成一格一格的粉色卡片
- **產出**：做完這批你就能停用 Notion 排任務，日常新增、勾選、查詢全部在工作台完成。網址是 `zhuer0323-tech.github.io/dora-workspace/`。
- **注意**：這批做完會請你**實際用一週**再往下做，因為第二批的看板要照你真實的使用習慣設計。

### Step 4：把 Notion 現有任務搬過來

- **做什麼**：寫一支只在你電腦上跑一次的小程式，把 Notion 計畫資料庫的任務讀出來，存成一個檔案；
  然後在工作台加一個「匯入」按鈕，你選那個檔案就全部進去。
- **產出**：你不用一筆筆重打。
- **為什麼要繞這一圈**：Step 2 把資料庫鎖成「只有登入的 Google 帳號能寫」之後，
  電腦上的腳本沒辦法直接寫進去（它沒有你的登入身分）。走「腳本產檔案 → 在已登入的工作台匯入」
  這條路，比去申請服務帳號金鑰簡單也安全得多。
- **注意**：搬完後 Notion 那邊的資料**不會刪**，先留著當備份。另外，你的 8:30 自動早報現在是讀 Notion 的，這支要改成讀工作台，這件事排在第二批之後做（第一批期間早報照舊讀 Notion，不會壞掉）。

### Step 5：第二批交付 —— 四個看板 + 甘特圖 + 超時提醒

- **做什麼**：
  - **日計畫**：一條從早上 8 點到半夜的時間軸，任務按預計時段貼上去
  - **週計畫**：一週七欄，上面是每日任務摘要，下面是時間軸
  - **月曆**：月曆格子裡塞當日任務，左側是本月統計
  - **年計畫**：12 個月小月曆 + 全年統計 + 每月完成率
  - **甘特圖**：左邊任務清單、右邊橫條進度圖，上方一排柱狀圖顯示每天有幾件任務（一眼看出哪幾天被塞爆）
  - **顏色規則**：綠＝已完成、紫＝進行中、黃＝未開始，全站通用
  - **超時提醒**：快到期限但還沒完成的任務，自動在首頁跳出來
- **產出**：填一次任務，五個看板同時自動更新，不用重複整理。
- **注意**：這些看板在手機上會很擠，會做成手機版只顯示重點、電腦版顯示完整。

### Step 6：第三批交付 —— 復盤與反思區

- **做什麼**：日復盤、週復盤、月總結三種紀錄，每一種都自動帶入該期間的任務完成狀況當作填寫依據；月總結自動收進年度檔案。
- **產出**：你現在用的學習日記（`000_Agent/memory/daily/`）可以接進來，寫完的內容同時看得到當天做了什麼。
- **注意**：這一批跟你現有的 `/journal` 工作流會有重疊，做之前會先確認是要合併還是並存。

### Step 7：把早報接到新工作台

- **做什麼**：把 8:30 自動早報的資料來源從 Notion 改成工作台。
- **產出**：早報卡片上的今日待辦，跟你工作台上看到的完全一致。
- **注意**：改完要連續觀察兩三天早上有沒有正常推播，確認沒問題才算完成。

## 可能遇到的風險

| 風險 | 怎麼處理 |
|:--|:--|
| ~~網址是公開的，任務裡有客戶名稱~~ ✅ 已處理 | 已改成 Google 帳號登入，資料庫規則綁定 zhuer0323@gmail.com。網頁本身仍是公開網址，但沒登入看到的只有登入畫面，一筆任務都讀不到。見 Step 2 的說明。 |
| **用一陣子後想大改任務欄位** | 所以 Step 3 做完會請你先用一週。這期間發現要改，改起來只影響一頁；等第二批五個看板都做完才改，五頁都要動。 |
| **雙時間軸的「預計時段」你懶得填** | 已經先砍掉實際軸。若連預計時段都覺得麻煩，日／週看板可以退回成「只分到哪一天」的清單模式，這個開關會做在設定裡。 |
| **Firebase 免費額度用完** | 你的資料量（一年幾千筆任務）遠低於免費額度，實務上不會遇到。會設定每月自動匯出一份備份到工作區資料夾。 |
| **搬家後 Notion 那邊還有人在看** | 舊資料不刪，Notion 頁面保留唯讀狀態，但明確標註「已停用，任務請看工作台」，避免兩邊都在填。 |
| **早報改來源時推播中斷** | Step 7 改完會保留舊版腳本，發現不對可以立刻切回去。 |
